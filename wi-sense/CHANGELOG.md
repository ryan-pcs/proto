## 2026-09-10
- Remediation completed: replaced exact packet/sample equality as the success gate with `sample_coverage_ratio` and `sample_coverage_acceptable`; the current threshold is 25%. Coverage above one is allowed because CSI callbacks can exceed UDP sends. The 240/500 run has 48% coverage and should be recollected under this policy rather than manually relabeled.
- Follow-up finding: removing periodic receiver readiness output fixed UART contention but exposed a reconnect bug. After one capture, the receiver remains running and no longer emits boot readiness text, so the next collector attempt can time out despite a healthy receiver. Replace passive boot-text detection with an explicit status handshake.
- Remediation completed: added the `CSI_STATUS` receiver command and changed the collector readiness check to use an explicit `RECEIVER_STATUS,ready=1,wifi=1` handshake. This preserves the single-writer CSI UART behavior while supporting repeated captures without rebooting the receiver.
- Hardware verification: after uploading the handshake firmware to COM4, a 5-second, 20 Hz run completed with 100 transmitter packets, 100 CSI samples, zero transmitter failures, `capture_status=success`, and `processing_status=success`.
- Capture finding: the 20-second, 20 Hz run at `01:16:35` attempted 400 sends, completed 313, and had 87 consecutive `WiFiUdp.endPacket()` failures (`error 12`) while the receiver collected 316 CSI rows. Coverage was 79%, but the run remains `partial` because transmitter send failures invalidate the burst. This is a transmitter/network runtime issue, not a missing-data or classifier issue.
- Hidden-bug audit: `wala` coverage of 1.0 still does not prove UDP-packet identity; `CSI_CAPTURE_OFF` is not acknowledged before the receiver closes, leaving a final-sample race; the 25% coverage threshold can accept heavily incomplete callback streams; the current `max_amplitude` feature is constant in the `wala` run because the invariant CSI prefix dominates it; CSV headers are accepted by column count without schema-name validation; and dataset validation does not recompute coverage from samples and transmitter packets. These are accuracy/data-integrity findings, not evidence that the classifier lacks enough data.
- Planned remediation: wait for `CSI_CAPTURE_STOPPED` before closing the receiver, validate exact firmware CSV headers, recompute metadata coverage from `samples / transmitter_packets`, and raise the minimum accepted CSI coverage to 75%. The raw CSI prefix will remain unchanged until its format is verified.
- Remediation completed: the collector now waits for `CSI_CAPTURE_STOPPED`, validates exact supported CSI header names, and the dataset report recomputes `sample_coverage_ratio` from raw counts. The minimum accepted coverage is now 75%; low-coverage captures remain archived. The raw CSI prefix remains unchanged pending format verification.
- New hidden-bug audit: non-finite CSI values such as `NaN` or `Infinity` can pass collector parsing; disarm failures are suppressed and can leave CSI enabled; the receiver caches the transmitter BSSID only at startup and can silently reject CSI after a transmitter AP reboot; dataset validation trusts the stored coverage-acceptable flag instead of enforcing the 75% threshold; mixed `empty`/`other` data in a training directory can raise a `KeyError`; and the latest `wala` `max_amplitude` feature is constant and carries no observed signal.
- Planned remediation: reject non-finite CSI values, make disarm confirmation part of capture success, refresh the transmitter BSSID on Wi-Fi reconnect, enforce the coverage threshold independently in dataset validation, reject unsupported training categories cleanly, and exclude the constant `max_amplitude` feature from the baseline classifier.
- Remediation completed: collector rejects non-finite CSI values and requires confirmed receiver shutdown; dataset reporting enforces the 75% coverage threshold and stop metadata; receiver refreshes the transmitter BSSID after reconnect; training rejects unsupported categories; and the baseline classifier excludes the constant `max_amplitude` features.
- Firmware-risk audit: CSI output is written synchronously from the Wi-Fi callback and can starve the radio/UART at higher rates; cancelling with `Q` skips the transmitter `STOP` path; zero-length CSI buffers are not rejected before `buf[0]` access; transmitter AP/UDP initialization return values are ignored; UDP pacing can burst after a stall; `beginPacket()`/`write()` results are ignored; receiver command handling can wait up to one second; and exact CSI-to-UDP correlation remains unavailable.
- Planned remediation: remove the interactive cancel path so every started burst has deterministic cleanup; add CSI length bounds; reduce receiver command latency; validate transmitter AP/UDP initialization and UDP packet construction; and reschedule UDP pacing after each send to avoid catch-up bursts.
- Remediation completed: removed the Q/cancel path and its documentation; added receiver CSI length bounds; reduced receiver command-loop delay to 10 ms; checked transmitter AP and UDP initialization; checked `beginPacket()` and `write()` results; and rescheduled transmitter pacing after each send to prevent catch-up bursts.
- High-risk callback remediation completed: CSI frames are now copied into a bounded FreeRTOS queue and formatted by a receiver worker task instead of being printed from the Wi-Fi callback. Queue drops are counted and invalidate the capture; shutdown waits for in-flight callback and queued output drain before acknowledging `CSI_CAPTURE_STOPPED`.
- Deep queue audit: stop acknowledgment can still race callback/task state; drained CSI rows are discarded by the collector while waiting for stop acknowledgment; `ets_printf` and `Serial` remain concurrent UART writers; a 3-second drain timeout is reported as successful stop; C5/C6 CSV labels differ from legacy schema labels; missing headers can still be inferred by column count; emergency cleanup disarms before stopping the transmitter; queue capacity is not rate-feasible for all advertised rates; task creation failure is unchecked; and transmitter initialization failure leaves a commandable but unusable loop.
- Ordered remediation plan recorded: make capture state and stop acknowledgment atomic/truthful; use one receiver UART output path; collect drained CSI rows before closing; stop the transmitter before receiver disarm during emergency cleanup; fail closed on transmitter initialization/task-creation errors; and reject CSI data until a validated header is present.
- Ordered remediation completed: receiver capture state now uses a critical-section boundary and truthful stop/timeout responses; receiver command responses and CSI output share `ets_printf`; the collector preserves CSI rows drained before stop acknowledgment; emergency cleanup stops the transmitter first; transmitter initialization/task failures fail closed; and CSI rows are rejected until an exact supported header is received.

- Remediation: added required separate train/test directories, nearest-centroid held-out accuracy, and a confusion matrix to the baseline model metadata. Evaluation remains blocked until separate `metal` and `non_metal` test captures exist.

- Follow-up audit: BSSID filtering is confirmed to exclude other source MACs but does not prove that a CSI row came from the UDP sensing packet; exact packet correlation remains unresolved. Capture timing can include pre-burst CSI and serial output can be interleaved or delayed. Feature normalization, derived-artifact validation, and train/test independence need strengthening before classifier accuracy is considered evidence of object detection. The raw CSI array prefix was reviewed and is not classified as metadata without format-specific proof.
- Remediation audit recorded before changes: confirm the remaining CSI-to-UDP identity limitation; synchronize capture collection around the burst; prevent readiness text from sharing the high-volume CSI output path; validate derived feature schema, frame counts, source identity, and finite values; normalize classifier features before distance calculation; and reject duplicate or overlapping train/test runs. - Remediation completed: the collector now flushes receiver input immediately before `START` instead of waiting through a pre-burst CSI window; receiver readiness is no longer emitted periodically over the CSI UART; malformed CSI rows are rejected before counting; and the receiver promiscuous filter accepts data frames only in addition to BSSID filtering.
- Remediation completed: dataset validation now checks filtered CSV rows, feature schema, source filename, frame count, required summaries, and finite values. Classifier training now standardizes features, stores the scaler, rejects overlapping run IDs/raw CSV hashes/object groups between train and test, and reports malformed feature errors cleanly.

- Capture-layer redesign: the receiver now starts with CSI capture disabled and accepts `CSI_CAPTURE_ON` / `CSI_CAPTURE_OFF` commands from the collector. The collector arms and flushes the receiver immediately before `START`, disarms it during cleanup, records `receiver_capture_armed`, and requires packet/sample agreement in dataset validation. This removes startup and pre-burst contamination without claiming exact UDP-payload correlation.
- Follow-up finding: exact transmitter-packet/CSI sample equality is too strict for this callback-based receiver. A controlled run sent 500 packets and produced 240 valid CSI rows with zero transmitter failures; because CSI callbacks are not guaranteed one-for-one with UDP packets, the run was archived as partial by policy even though it may be useful. Replace equality with an explicit coverage ratio and documented threshold while retaining the packet-correlation limitation.
